Technical Design & Architecture Document

Target Audience: Principal / Head Software Engineer

1. Executive Summary

Text2Chart is a robust, local-first Streamlit application designed to bridge the gap between natural language and database visualization. It translates user queries into syntactically valid Microsoft SQL Server (T-SQL) statements via an OpenAI-compatible LLM (e.g., LM Studio), executes them securely against a target database, and presents the results dynamically as either formatted DataFrames or interactive Plotly charts.

The architecture heavily emphasizes a seamless, modern User Experience (UX), employing significant JavaScript and CSS injection to bypass Streamlit's native limitations (e.g., custom autocomplete overlays, DOM manipulation for popovers). It prioritizes deterministic SQL generation, robust error handling, query execution timeouts, and smart visual heuristics.

2. Architecture Overview

The application follows a modular, state-driven architecture within the Streamlit lifecycle:

  • State Management: Streamlit's session_state manages the DB connections, AI client, chat history, and UI interaction flags.
  • Frontend Layer: Streamlit core components augmented by custom CSS (style_manager.py) and injected vanilla JavaScript for advanced interactions (ui_components.py).
  • Orchestration Layer: app.py acts as the controller, coordinating between the UI, AI, and DB managers.
  • Data Access Layer: db_manager.py handles pyodbc connections, advanced schema extraction, and chunked query execution.
  • Intelligence Layer: ai_manager.py interacts with the local LLM, utilizing a dense, rule-based system prompt to ensure precise T-SQL generation.
  • Visualization Layer: chart_utils.py applies heuristics to map DataFrame structures to Plotly Express charts.

3. Detailed Module Analysis

Application Entry & Orchestration app.py

  • Session Initialization: Initializes critical state variables (messages, db_manager, ai_manager, schema_context) on the first run.
  • Auto-Connect: Implements a one-time auto-connect routine using credentials from settings.ini to bypass the configuration screen on startup if credentials exist.
  • Chat Loop: Iterates over session messages. Employs conditional rendering based on message types (user, error, dataframe, chart).
  • Message Actions (Popovers): Uses Streamlit popovers (st.popover) to inject contextual menus on past messages (e.g., converting a DataFrame to a Bar/Line/Pie chart, editing an existing chart, or deleting a message).
  • JS Event Triggering: To handle the asynchronous nature of Streamlit, actions triggered from popovers set a flag. A hidden HTML component injects a mock click event on the parent document's body to force the popover to close immediately.
  • AI Execution Pipeline:
    1. Appends the user query to the UI.
    2. Injects a high-performance JavaScript timer for real-time latency feedback without triggering Python re-runs.
    3. Sends schema, history (last 6 messages max), and prompt to the AI.
    4. Parses the returned SQL, executes it via db_manager, and renders the result.

UI Components & Frontend Engineering ui_components.py

  • Advanced Autocomplete System: Overcomes Streamlit's lack of native chat input autocomplete.
    • Injects a sophisticated Vanilla JS script that attaches listeners to the Streamlit chat input.
    • Dynamically filters a JSON-serialized user history array.
    • Renders a custom floating DOM element perfectly positioned above the input box.
    • Supports full keyboard navigation and seamlessly updates the React-controlled textarea.
  • Smart DataFrame Rendering:
    • Link Injection: Uses Regex to detect 'address' columns and wraps them in Google Maps URLs.
    • Dynamic Formatting: Inspects column names for keywords ('amount', 'pct', etc.) and applies Pandas Styler formatting.
    • Deduplication: Safely deduplicates identical column names to prevent PyArrow serialization crashes.
  • Chart Editor UI: Provides a bounded state for modifying an existing chart, allowing users to override axes and manually reorder categorical axes.
  • Sidebar History Management: Implements a highly customized, tight-layout history view with extensively styled deletion and population buttons.

Database Management & Schema Extraction db_manager.py

  • ODBC Connection: Utilizes pyodbc with the standard 'ODBC Driver 17 for SQL Server'.
  • Advanced Schema Extraction: Uses heavy, optimized system queries to extract:
    1. Base tables and column types.
    2. Foreign Key relationships.
    3. Index definitions (Primary Keys, Unique constraints).
    4. Extended Properties.
    This rich context is optimized for LLM token efficiency, allowing implicit understanding of relationships.
  • Safe Execution & Chunking:
    • Server-Side Timeout: Hard-caps the connection timeout to 20 seconds.
    • Client-Side Chunking: Reads large result sets using chunked pandas reads. Aborts if it exceeds 20 seconds.
    • 1-Indexed Dataframes: Adjusts the Pandas index to start at 1 to align with non-programmer expectations.

AI Orchestration ai_manager.py

  • Client Initialization: Configured for OpenAI's API standard, allowing drop-in compatibility with local models via LM Studio.
  • System Prompt Engineering: Highly prescriptive prompt locking the LLM into specific behaviors:
    • Security: Explicit rules denying DDL/DML operations and enforcing schema-only querying.
    • Syntax Strictness: Enforces standard T-SQL, strict bracket encapsulation, and safe casting.
    • Limits: Mandates SELECT TOP 1000 by default.
    • Logic Enforcement: Strict rules on explicit GROUP BY inclusion.
  • Domain Specific Injectors: Dynamically appends rules based on the active database (e.g., OpenDB wildcard rules, BankDB monetary rules).
  • Sanitization: Strips markdown code blocks via Regex before execution.

Charting & Visualization chart_utils.py

  • Plotly Express Wrapper: Generates interactive Bar, Line, and Pie Plotly figures.
  • Heuristic Data Mapping: If X/Y columns aren't provided, analyzes df.dtypes to find the first string column (X-axis) and first numeric column (Y-axis).
  • Reindexing Logic: Safely checks intersection of requested order list and actual data values, utilizing reindex() to force precise visual order.

Configuration & Settings config_manager.py

  • Built on Python's configparser to maintain state cleanly in a settings.ini file.
  • Separates database connection data from AI parameters, providing sensible defaults to quickly unblock users starting fresh.

Styling & CSS Architecture style_manager.py

  • Component Overrides: Injects global styles overriding the Streamlit DOM.
  • Visual Polish: Implements dark mode UI, tightens button paddings, hides the "Deploy" header cleanly, and styles chat bubbles with distinct alignment.
  • Flexbox Hacks: Heavy use of flexbox and absolute positioning to create a "borderless" feel for the history item lists, targeting Streamlit's inner divs for pixel-perfect alignment.

4. Security & Constraints

  • Read-Only Enforcement: Relies heavily on the LLM prompt to refuse DML/DDL commands. (Note: Should ideally be paired with an isolated, read-only SQL Server service account).
  • Resource Exhaustion Prevention: Both query generation (SELECT TOP 1000) and execution (timeout=20s, chunked pandas reads) are designed to prevent hanging or crashing the database server.
  • SQL Injection: Executes whatever SQL the LLM generates. Classic SQL injection via input is mitigated (no direct concatenation), but prompt injection resulting in malicious SELECT queries remains a vector.
